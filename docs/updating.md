# Обновление установленной версии

Обновляется установленное приложение Windows x64 (`desktop/`, ADR 0001 §5). Сборка разработчика
(`npm run start`) не обновляется.

## Заставка при запуске (T58)

Как в Discord: **сначала заставка, потом Cord.** При запуске открывается маленькое тёмное окно без рамки
(`cord-app://shell/splash`, 300×360 по центру экрана) — знак Cord и одна строка:

1. «Проверяем обновления…» — вопрос к зеркалу, на ответ 5 секунд;
2. «Загружаем обновление… 42%» и тонкая полоса — если есть версия новее установленной;
3. «Устанавливаем…» — тихая установка NSIS и перезапуск.

Главное окно и страница сервера создаются **только после заставки**. Кнопки «позже» нет: найденное
обновление ставится при открытии. Зеркало молчит, отвечает ошибкой или неподписанным описанием — Cord
открывается как обычно и переспросит через 10 минут. Сбой загрузки или установки — короткая строка на
заставке, «Повторить» и «Открыть Cord»; отказ установщика виден на следующем запуске (перед установкой
запоминается ожидаемая версия) и сам не повторяется. Откатов нет (`allowDowngrade: false`).

Пока Cord открыт, проверка — раз в 6 часов. Во встрече обновление не качается и не ставится: ждёт её
конца или следующего запуска. Номер версии виден только в «О программе».

## Канал на зеркале

electron-updater, generic-провайдер, адрес **вшит при сборке** и не следует за выбранным сервером встреч:
вход в чужую комнату не должен решать, какой исполняемый файл поставится. Канал —
`https://<зеркало>/downloads/windows/desktop/`:

- `latest.yml` — описание выпуска electron-builder (версия, `Cord-Setup-X.Y.Z.exe`, размер, sha512), в которое
  `scripts/sign-manifest.mjs` дописывает `sha256` каждого файла;
- `latest.yml.sig` — подпись Ed25519 над точными байтами `latest.yml`. Ключи проверки `[текущий, следующий]`
  вшиты в сборку (`desktop/build/update-keys.json`); закрытый ключ — только у владельца, в секрете CI
  `CORD_UPDATE_SIGN_KEY`. Без подписи клиент описание **не принимает**: это обязательный слой, пока нет
  сертификата Authenticode;
- `Cord-Setup-X.Y.Z.exe` и `.exe.blockmap` — установщик и карта блоков: качаются только изменившиеся куски,
  предыдущий выпуск остаётся в канале для дельт.

Проверки клиента по слоям: подпись описания → адрес файла только внутри канала → размер и sha512
(electron-updater) → sha256 из подписанного описания против файла на диске → тихая установка NSIS с
перезапуском.

## Выкладка

CI `desktop.yml` публикует релиз `desktop-vX.Y.Z` на GitHub; на зеркало его кладёт
`backlog/bin/publish-windows.sh --desktop X.Y.Z` из репозитория ядра: файлы — в `desktop/`, `latest.yml` пишется
последним, `download.json` в корне получает у файла `path: "desktop/"`, чтобы страница `/download` вела в
канал. Пошагово — [`docs/RELEASE.md`](https://github.com/MikkiMays/ModernStreamingSystem/blob/main/docs/RELEASE.md)
репозитория ядра.

## Проверки

Модульные тесты `desktop/test/unit` (`splash-flow` — шаги заставки, `manifest` — подпись описания), смоук Playwright
`_electron` и в CI проверка собранного установщика: тихая установка, удаление и **обновление поверх
настоящего прошлого выпуска**. Вид заставки на разных DPI и переход между двумя опубликованными выпусками
на живой машине — отдельная приёмка.
