# Обновление установленной версии

Первый поддерживаемый вариант — установленное приложение Windows x64. При запуске и каждые шесть часов приложение читает последний стабильный релиз фиксированного репозитория `MikkiMays/ModernStreamingSystem.Windows`. До нажатия «Обновить» пакет не скачивается.

**Спросить самому можно в одном месте** — «О программе» на странице настроек, которую приложение делит с веб-клиентом. До 0.7.1 такая же кнопка была ещё и в боковой панели: два места для одного вопроса — это не удобство, а необходимость помнить, какое из них главное. В панели осталась строка версии, а под ней — плашка, когда обновление есть. Строки «установлена последняя версия» там нет: это не новость, а её отсутствие.

Найденное обновление показывается плашкой в боковой панели, а когда окно свёрнуто — коротким уведомлением Windows, **один раз на версию**. Уведомления — попытка, а не требование: Cord ставится без пакета (`WindowsPackageType None`), и регистрация может отказать; отказ означает отсутствие уведомления и ничего больше. Регистрация снимается при закрытии окна: оставленная, она превращает нажатие на старое уведомление в запуск второго экземпляра.

Принимается только новая версия `X.Y.Z`, не draft/prerelease, с точным именем `Cord-Setup-X.Y.Z-x64.exe` и SHA-256 `digest` GitHub. Загрузка и перенаправления допускают только HTTPS и разрешённые хосты GitHub. Размер и хеш проверяются до перемещения `.partial` в готовый файл. Неудачная загрузка оставляет установленную версию и даёт повторить попытку.

Во время встречи скачанный пакет ждёт. После её завершения помощник читает UTF-8 JSON-план, проверяет SHA-256 средствами .NET и создаёт файл готовности. Cord закрывается только после этой готовности и повторной проверки отсутствия звонка. Помощник ждёт завершения процесса, повторно проверяет пакет и запускает существующий Inno Setup:

`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /NOCANCEL /CLOSEAPPLICATIONS /DIR="текущий каталог" /LOG="журнал"`

AppId остаётся прежним; профиль WebView2, избранное и настройки расположены вне заменяемых файлов. Приложение запускается снова по окончании.

**Почему «обновил — а версия прежняя» (исправлено в 0.7.5).** Установщик заменяет файлы, которые держит открытыми любой процесс из каталога установки. Помощник ждал ровно один процесс — тот, что попросил обновиться; второе окно Cord или процесс, закрывший окно, но не вышедший, оставляли файлы занятыми, установщик отказывал, а приложение перезапускалось прежней версией. Причина отказа при этом стиралась при следующем запуске и показывалась как «Соединение». Теперь помощник:

- ждёт свой процесс 30 секунд и завершает его, если окно закрыто, а процесс не вышел;
- просит закрыться всё, что запущено из каталога установки, и через 20 секунд завершает оставшееся;
- повторяет установку один раз после трёхсекундной паузы;
- сверяет `FileVersion` у `Cord.exe` на диске с ожидаемой версией (план несёт `Version`), а не верит коду выхода;
- пишет шаги в `updates/update.log`, итог — в `result.json` (этап, код Inno Setup, хвост `installer.log`).

При следующем запуске итог показывается плашкой «Обновление» — и успех, и причина словами — и остаётся в `updates/result-last.json`. Помощник обязан оставаться ASCII: Windows PowerShell 5.1 читает файл без BOM в кодировке ANSI.

Переход на исправленный помощник выполняет ещё прежний: у кого обновление не ставилось, тот ставит 0.7.5 один раз вручную поверх установленной.

[Параметры Inno Setup](https://jrsoftware.org/ishelp/topic_setupcmdline.htm). 0.3.0 не содержит загрузчика: нужен один переходный запуск нового установщика. Portable ZIP не определяется как установленная версия и автоматически не обновляется.

`ReleaseTests` проверяет версии, архитектуру, origin, HTTPS, размер и хеш. `scripts/test-installer.ps1` запускает настоящий установщик и тот же помощник, который включён в приложение: каталог с пробелом/кириллицей, ожидание живого родителя, повреждённый пакет, повторное применение, сверку версии на диске, **другой Cord, запущенный из каталога установки** (помощник обязан убрать его сам), профиль и запись удаления. `--verify-service` дополнительно проверяет возврат размеров после нативного fullscreen и сохранение WebView2. Физический звонок, DPI, обрыв сети и переход между двумя опубликованными релизами по-прежнему требуют отдельной приёмки.

## Только зеркало Cord (с 0.7.6)

Клиент спрашивает обновление **только** у зеркала `https://meet.nikg.tech/downloads/windows/latest.json`,
анонимно, без учётных данных. GitHub из клиента убран: репозитории Cord приватные (анонимный API
отвечает 404), и Cord — продукт, который не отправляет людей на внешние адреса. Перенаправление с
зеркала куда-либо, кроме `/downloads/windows/` того же хоста, отклоняется.

Зеркало хранит исходный JSON релиза сборочного конвейера целиком и явно называет репозиторий, поэтому
проверка прежняя: имена, размеры и SHA-256 обязаны совпасть с объявленными, адрес пакета
пересобирается на адрес зеркала. Отвергнутый релиз — с чужим адресом пакета или без проверяемой суммы —
останавливает обновление; другого источника клиент не ищет. Пустое зеркало (404) — «обновлений нет».

**Доставка на зеркало — обязательный шаг выпуска.** После зелёного Windows CI и публикации релиза
оператор выкладки скачивает его и публикует `ModernStreamingSystem/scripts/publish-windows-release.py`
вместе с JSON релиза (скилл `cord-deploy`, раздел «Релиз Windows»). Скрипт проверяет все хеши и
обновляет указатель `latest` только после полной записи файлов; старые версии сохраняются, перезапись
существующего релиза другим содержимым запрещена. GitHub Actions доступа на сервер не имеет. Пока
выпуск не выложен на зеркало, ни клиенты, ни страница `/download` его не видят.

Клиенты 0.7.5 и старше спрашивают сначала GitHub, получают 404 и уходят на то же зеркало — до 0.7.6
они обновятся без ручных шагов.
