# Установка и распространение Cord

Для передачи приложения достаточно одного файла **`Cord-Setup-<версия>-x64.exe`**. Установщик содержит приложение, его библиотеки, ресурсы WinUI/XAML, .NET, Windows App SDK и полный автономный установщик Microsoft Edge WebView2 Runtime. Копировать DLL или распаковывать ZIP вручную не требуется.

Номер версии здесь намеренно не указан: берите файл со страницы `/download` **того сервера, которым пользуетесь**, или из [последнего релиза](https://github.com/MikkiMays/ModernStreamingSystem.Windows/releases/latest) — оба всегда актуальны. Страница скачивания на сервере показывает версию, размер и SHA-256 и отдаёт файл с того же домена, без GitHub-аккаунта.

Готовые файлы находятся в [последнем GitHub Release](https://github.com/MikkiMays/ModernStreamingSystem.Windows/releases/latest). Путь `artifacts/` относится к локальной сборке; в Git сохраняются исходники, а установщик, переносимый ZIP и SHA-256 прикрепляются к релизу.

## Установка

1. Передайте `Cord-Setup-<версия>-x64.exe` на компьютер с Windows x64. Минимум — Windows 10 build 19041; предпочтительно Windows 11.
2. Запустите установщик. Приложение устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\Cord`, без запроса прав администратора. Папку можно изменить.
3. Установщик создаёт пункт Cord в меню «Пуск»; ярлык рабочего стола выбирается отдельно. WebView2 устанавливается из включённого пакета, только если Runtime отсутствует.
4. Откройте Cord. Сервера по умолчанию у него нет: при первом запуске он спрашивает адрес, и этот адрес — тот самый, с которого установщик скачали. Дальше сервер сохраняется, подключается сам при запуске, а новые добавляются кнопкой в том же окне. При обновлении сохранённый список серверов не меняется.

Файлы установки доступны без скачивания зависимостей. Для звонков нужен доступ к общему серверу: установщик не содержит VPS, Java-ядро, базы данных или LiveKit. Веб-интерфейс загружается с выбранного сервера. Для локальной разработки можно вручную выбрать `http://localhost:5173`; обычной установке локальный сервер не нужен.

## Предупреждение SmartScreen и подпись

Наш EXE не подписан сертификатом издателя, поэтому Windows показывает «Система Windows защитила ваш компьютер» и называет издателя неизвестным. **Убрать это изнутри установщика нельзя.** Права администратора не помогают: SmartScreen к ним не относится, а установка у нас и так идёт без повышения прав (`PrivilegesRequired=lowest`), то есть лишнего окна UAC нет. Отключение SmartScreen — настройка на стороне того, кто скачивает, и просить об этом нельзя.

Что решает вопрос — только подпись Authenticode сертификатом, которому Windows доверяет:

| Вариант | Что даёт |
| --- | --- |
| Без сертификата (сейчас) | Предупреждение на каждой новой версии; репутация копится по хешу файла и обнуляется с каждой сборкой |
| OV-сертификат | Издатель назван; репутация копится по сертификату и переживает новые версии, но первые загрузки всё ещё предупреждают |
| EV-сертификат или [Microsoft Artifact Signing](https://learn.microsoft.com/en-us/azure/artifact-signing/overview) (бывший Trusted Signing) | Предупреждения нет практически сразу |

Про Artifact Signing стоит знать заранее, **кому он вообще доступен**. Из
[инструкции Microsoft](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart):
сертификаты Public Trust выдаются организациям из США, Канады, ЕС, Великобритании, Австралии,
Новой Зеландии, Японии, Южной Кореи, Сингапура, Швейцарии, Норвегии и Израиля, а
**индивидуальным разработчикам — только из США и Канады**. Без юрлица из этого списка дешёвый
путь закрыт, и остаётся обычный OV/EV-сертификат у удостоверяющего центра.

Цена Basic — **$9.99 в месяц** за 5 000 подписей, сверх квоты $0.005 за подпись (по
[розничному прайс-API Azure](https://prices.azure.com/api/retail/prices?$filter=serviceName%20eq%20%27Trusted%20Signing%27),
на 15.09.2026; на самой странице цен числа подгружаются скриптом и в тексте их нет). Проверка
личности идёт от 1 до 20 рабочих дней.

Сборка к этому готова: `scripts/sign.ps1` вызывается из `build.ps1` (для `Cord.exe`, до упаковки ZIP) и из `build-installer.ps1` (для готового Setup, до подсчёта SHA-256). Без сертификата он ничего не делает и пишет об этом в лог — сборка ведёт себя ровно как раньше. Чтобы включить подпись, задайте секреты:

| Переменная | Значение |
| --- | --- |
| `CORD_SIGN_PFX_BASE64` | файл `.pfx`, закодированный в base64 |
| `CORD_SIGN_PASSWORD` | пароль к нему, если есть |
| `CORD_SIGN_TIMESTAMP_URL` | служба меток времени RFC 3161; по умолчанию DigiCert |

Метка времени обязательна на практике: без неё все подписи перестают проверяться в день истечения сертификата — включая те копии, которые люди уже установили.

Отдельно: если Microsoft Defender пометит файл ошибочно, это **не** SmartScreen и лечится [заявкой на анализ файла](https://www.microsoft.com/en-us/wdsi/filesubmission) — бесплатно.

Включённые установщики зависимостей проверены по SHA-256 и цифровой подписи их производителей.

## Обновление и удаление

Cord проверяет обновления сам — при запуске и далее раз в шесть часов — и предлагает установить новую версию. Проверяются издатель, версия, адрес, размер и SHA-256 пакета; подробности в [updating.md](updating.md). Канал обновлений фиксирован и **не** зависит от того, к какому серверу вы подключены.

Установить новую версию можно и вручную, поверх существующей: постоянный AppId сохраняет установочную запись и выбранный каталог. Перед обновлением завершите звонок; установщик умеет предложить закрыть занятые файлы приложения.

Удаление доступно в Windows → «Параметры» → «Приложения» → Cord. Оно удаляет установленные файлы и ярлыки, но сохраняет `%LOCALAPPDATA%\Cord` с настройками и профилями, а также общий WebView2 Runtime. Повторная установка под тем же пользователем сможет использовать сохранённое имя, настройки сервера и профиль избранного. Файлы, которые пользователь сам скачал, установщику не принадлежат.

Параллельно остаётся переносимый вариант `artifacts/Cord-win-x64.zip` (90 МиБ). Его нужно распаковать полностью; ему требуется уже установленный WebView2 Runtime. Один `Cord.exe` из этого ZIP не является самостоятельным приложением.

## Сборка и проверка

Из корня Windows-проекта в PowerShell 7:

```powershell
# Тесты, self-contained публикация, ZIP, загрузка проверенных зависимостей, Setup
.\scripts\build-installer.ps1

# Пересобрать только установщик из готовой публикации
.\scripts\build-installer.ps1 -SkipPublish

# Загрузить настоящие ресурсы App/MainWindow без открытия окна или подключения к серверу
.\scripts\verify-publication.ps1

# Установка, повторная установка и удаление в собственной временной папке
.\scripts\test-installer.ps1

# Настоящий WebView2/React, публичный HTTPS и native API с новым профилем
.\scripts\verify-service.ps1

Get-ChildItem .\artifacts\Cord-Setup-*-x64.exe | Get-FileHash -Algorithm SHA256
Get-Content .\artifacts\Cord-Setup-*-x64.exe.sha256
```

Сценарий проверки установщика отказывается работать, если Cord уже установлен: он не должен заменять пользовательскую установку тестовой. Ему нужен имеющийся WebView2, чтобы проверка не меняла общую системную зависимость. Логи остаются в `.local/installer-smoke`. Удаляется только тестовая установка, созданная этим запуском; добавленный проверкой посторонний файл сохраняется.

Версии и хеши Inno Setup 7.1.0 и автономного пакета WebView2 закреплены в `installer/dependencies.json`. Скрипт сборки проверяет и хеш, и издателя Authenticode; компилятор размещается в `.local/installer-tools`. Манифест зависимостей следует обновлять осознанно, включая повторную проверку подписи. Установщик, ZIP и контрольная сумма включены в Windows workflow. [Первый удалённый CI-прогон](https://github.com/MikkiMays/ModernStreamingSystem.Windows/actions/runs/34319798573) 9 сентября 2026 успешно проверил сборку, тесты, загрузку WinUI-ресурсов и создание установщика на Windows runner.

## Проверено 8 сентября 2026

- 16 C#-тестов и Release-публикация.
- Наличие обязательных `Cord.pri`, `App.xbf`, `MainWindow.xbf`, библиотек и значка в опубликованной папке.
- Реальная загрузка WinUI `MainWindow.xaml` через `--verify-resources`, без активации окна, обращения к серверу и захвата устройств.
- Тихая установка в путь с пробелом и кириллицей, запись удаления в Windows, повторная установка, повторная загрузка XAML и удаление. Посторонний файл сохранён, запись приложения удалена.

При проверке найден и исправлен дефект публикации: обычный `dotnet publish` не включал PRI/XBF, хотя сборка завершалась успешно. В проект добавлено явное копирование этих ресурсов после Publish; проверка загрузки защищает от повторения. Аналогичная проблема описана в [Windows App SDK issue 6720](https://github.com/microsoft/WindowsAppSDK/issues/6720).

Установка зависимости на чистой Windows без WebView2 ещё требует проверки в отдельной VM. На текущем компьютере Runtime уже есть. Проверка ресурсов не является визуальной проверкой анимации, разрешений камеры или реального звонка. Ручное управление окнами было остановлено по пользовательскому Escape.

Первичные источники: [распространение WebView2, автономный пакет и проверка Runtime](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution), [Inno Setup](https://jrsoftware.org/isdl.php), [установка без повышения прав](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm).
