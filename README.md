# Cord для Windows

C#-приложение для общего ядра ModernStreamingSystem. Нативное окно WinUI 3: Mica, спокойная боковая панель, системная тема, избранное и настройки сервера. Встреча работает внутри постоянного WebView2 через тот же React/LiveKit-клиент, что и браузер. Поэтому телефон, веб и Windows входят в одни комнаты, используют общие права, чат, файлы и правила восстановления.

## Запуск готовой сборки

Скачайте **[`Cord-Setup-<версия>-x64.exe` из последнего релиза](https://github.com/MikkiMays/ModernStreamingSystem.Windows/releases/latest)** и запустите его. Для передачи на другой компьютер достаточно этого одного файла: установщик включает приложение, библиотеки, .NET, Windows App SDK и автономный пакет WebView2 Runtime. Установка выполняется для текущего пользователя без прав администратора, создаёт ярлык в «Пуск» и поддерживает обновление/удаление. [Подробная инструкция](docs/installer.md).

В том же релизе доступен переносимый `Cord-win-x64.zip`: распакуйте **всю** папку и запустите `Cord.exe`. Он требует установленный WebView2 Runtime. Сборки предназначены для Windows x64, минимум Windows 10 build 19041; рекомендуемая система — Windows 11. Наш установщик пока не подписан сертификатом издателя. При локальной сборке эти файлы создаются в `artifacts/`; бинарные файлы распространяются через Releases, исходники — через Git.

Ядро, веб-клиент и VPS-конфигурация находятся в [ModernStreamingSystem](https://github.com/MikkiMays/ModernStreamingSystem). Для совместной разработки клонируйте оба репозитория в соседние каталоги:

```powershell
git clone https://github.com/MikkiMays/ModernStreamingSystem.git
git clone https://github.com/MikkiMays/ModernStreamingSystem.Windows.git
```

## Сначала сервер, потом встречи

Cord открывается на экране подключения. Пока сервер не ответил, ничего о встречах не
показывается: избранное принадлежит серверу, и показывать комнаты одного сервера, будучи
подключённым к другому, было бы неправдой.

На экране — список серверов: свой, рабочий, друга. Каждый — строка с именем, **точкой
доступности** рядом с ним и **шестерёнкой** в конце для изменения или удаления; ниже кнопка
добавления, а если серверов ещё нет — одна большая. Точки приложение проверяет само: оно, в
отличие от браузера, может спросить любой адрес. Сервер с включённым автоподключением
открывается сразу, без вопросов.

| Поле                    | Что делает                                                       |
| ----------------------- | ---------------------------------------------------------------- |
| Название сервера        | произвольная подпись для себя                                    |
| Адрес сервера           | `https://meet.example.com` или `https://203.0.113.10`            |
| Пароль                  | если сервер закрыт паролем; хранится под DPAPI, отдельно на сервер |
| Подключаться автоматически | открывать этот сервер при запуске                            |
| Добавить / Сохранить    | записать сервер, даже если он сейчас не поднят                   |

Отдельной проверки нет: подключение и есть проверка. Окно закрывается только при успехе; отказ
оставляет внизу слева красное «Не подключено» со стрелочкой, под которой написано, что именно не
так: пароль не тот, адрес не тот, сертификат не принят, сервер ещё запускается.

Вписывать нужно адрес **веб-приложения**, целиком со `https://` и без пути. Отдельный адрес
LiveKit указывать не нужно — клиент обращается к `/api/v1` и `/rtc` того же origin.

Имя и картинку профиля открывает блок профиля в левом нижнем углу — там же, где они показаны:
выбранная картинка появляется в этом кружке. Картинка живёт в странице, отдельно для каждого
сервера, поэтому её редактор один и тот же в браузере и в приложении.

**Настройки** — одни на всё приложение. Кнопка слева и блок профиля открывают ту же страницу
настроек, что и шестерёнка в вебе: устройства, обработка звука и звуки уведомлений, качество
камеры и экрана, имя и картинка, сервер и автоподключение, оформление, горячие клавиши,
диагностика. Отдельного маленького диалога с копией нескольких полей больше нет. Настройки
открываются и посреди встречи, не прерывая её; список серверов остаётся нативным.

Пароль сервера приложение запоминает зашифрованным средствами Windows для вашей учётной
записи. В `settings.json` он не попадает — этот файл переносят между машинами. Странице внутри
WebView2 передаётся только короткоживущий пропуск; когда он истекает, приложение молча берёт
новый, не прерывая встречу.

У каждого сервера свой профиль: имя, избранные комнаты, устройства и выданные разрешения
хранятся раздельно и не смешиваются при переключении. Адрес принимается только по HTTPS;
исключение — `localhost` для локальной разработки. Это не наше ограничение, а требование
защищённого контекста: без него браузерный движок не даст доступ к камере и микрофону.

Обновления самого приложения приходят с одного фиксированного адреса и **не** следуют за
выбранным сервером: подключение к чужой комнате не должно решать, какой исполняемый файл
установится на ваш компьютер. Адрес по умолчанию и канал обновлений заданы в одном месте —
`src/Cord.Core/CordDefaults.cs`.

## Скачать

**[meet.nikg.tech/download](https://meet.nikg.tech/download)** — установщик с того же домена, с
версией, размером и SHA-256 на странице. GitHub-аккаунт не нужен. Ту же страницу отдаёт любой
сервер Cord, чей владелец опубликовал сборку у себя; где сборки нет, страница честно об этом
говорит и предлагает браузер.

Windows покажет «Система Windows защитила ваш компьютер» и назовёт издателя неизвестным:
установщик не подписан сертификатом издателя. **Изнутри установщика это не убирается** — права
администратора тут ни при чём, а установка и так идёт без повышения прав. Нужно нажать
«Подробнее» → «Выполнить в любом случае». Что именно решает вопрос и как включить подпись одной
парой секретов — [installer.md](docs/installer.md#предупреждение-smartscreen-и-подпись).

Как поднять собственный сервер — [инструкция в основном репозитории](https://github.com/MikkiMays/ModernStreamingSystem/blob/main/docs/INSTALL.md).

По умолчанию новая установка подключается к **`https://meet.nikg.tech`**. Ранее сохранённый адрес сервера сохраняется при обновлении и открывается автоматически. Для локальной разработки укажите `http://localhost:5173` в настройках и запустите ядро из соседнего проекта:

```powershell
cd ..\ModernStreamingSystem
.\scripts\start-local.ps1 -JavaHome C:\Java\jdk-25
```

Чтобы использовать другой сервер, укажите HTTPS-адрес **веб-приложения** в настройках Cord. Приложение обращается к `/api/v1` этого же origin. URL отдельного LiveKit указывать здесь не нужно. `localhost` относится только к текущему компьютеру; для телефона и других компьютеров нужен общий HTTPS-сервер. Сборка не запускает VPS/ядро внутри себя.

## Возможности

- Главная, создание встречи, вход по ссылке/девятизначному коду, до пяти избранных комнат под основными кнопками и в нативной панели.
- Сохранённая комната сохраняет название и код, пока есть в избранном хотя бы одного профиля. Завершённый разговор можно открыть снова; сроки старых сообщений и файлов не продлеваются.
- Имя, устройства, тема и профили качества сохраняются между запусками. Название встречи задаётся при создании. Камера и микрофон по умолчанию выключены.
- На предпросмотре шестерёнка в правом нижнем углу открывает устройства и качество. Разрешения камеры/микрофона запрашиваются нативным диалогом; разрешённый доступ запоминается профилем WebView2 этого сервера. Отдельной кнопки сброса нет: разрешение снимается вместе с каталогом сервера в `%LOCALAPPDATA%\Cord\WebView2`.
- Общие звонки, демонстрация до 1440p60, 15/30/60 fps, сообщения и временные файлы. Просмотр экрана и камеры ведущего в углу или рядом, личное закрепление участника и экрана.
- Уведомление Windows о смене сети ускоряет общий механизм восстановления с фиксированным сроком 20 секунд. Ручной/автоматический возврат подписок к живому эфиру не перезапускает собственный захват.
- Компактная панель подключения по центру главной без прокрутки страницы. На низком окне избранное открывается отдельным диалогом. Нативный SplitView анимирует сворачивание боковой панели; постоянный WebView2 и медиасессия сохраняются. На узком окне навигация и настройки остаются в меню. Размер при запуске учитывает рабочую область монитора. Полноэкранная демонстрация скрывает оболочку и занимает монитор. Закрытие во время звонка отправляет явный выход.

Избранное принадлежит анонимному профилю клиента. Установка Windows и отдельный браузер имеют разные профили; вход на другом устройстве возможен по приглашению/коду, после чего комнату можно сохранить там. Автоматической синхронизации профилей между устройствами пока нет.

## Сборка из исходников

Из корня этого каталога, PowerShell:

```powershell
# Скачает локальный SDK с проверкой SHA-512, выполнит тесты, соберёт Release
.\scripts\build.ps1

# Тесты, автономная публикация, ZIP и его SHA-256
.\scripts\build.ps1 -Publish

# Публикация и отдельный установщик со всеми зависимостями
.\scripts\build-installer.ps1

# Проверка ресурсов опубликованного WinUI и полного цикла установки
.\scripts\verify-publication.ps1
.\scripts\test-installer.ps1

# Запуск опубликованного приложения; при отсутствии сначала соберёт его
.\scripts\run.ps1
```

Глобальная установка .NET/Visual Studio не требуется для этих скриптов. Первый запуск скачивает SDK и пакеты NuGet. Версии закреплены `global.json`, `.csproj` и `packages.lock.json`.

```powershell
.\.local\dotnet\dotnet.exe restore Cord.slnx --locked-mode -p:Platform=x64
.\.local\dotnet\dotnet.exe test --project tests/Cord.Core.Tests/Cord.Core.Tests.csproj
.\.local\dotnet\dotnet.exe format whitespace Cord.slnx --verify-no-changes --no-restore
```

Тесты используют xUnit 4 и Microsoft.Testing.Platform; `--nologo` не является параметром этого тестового runner.

## Структура и данные

| Каталог | Ответственность |
| --- | --- |
| `src/Cord.Core` | Проверка server origin, HTTP-контракт избранного, типизированный bridge, source-generated JSON |
| `src/Cord.Windows` | WinUI, MVVM, WebView2, диалоги, жизненный цикл окна, DPAPI и сеть |
| `tests/Cord.Core.Tests` | Origin/bridge, HTTP-контракт, изоляция и постоянство профилей |
| `scripts` | Сборка, публикация и проверки установки/удаления |
| `installer` | Установщик Inno Setup, закреплённые зависимости и информация об установке |
| `.github/workflows/windows.yml` | Сборка, тесты и артефакт на Windows runner |

Настройки находятся в `%LOCALAPPDATA%\Cord\settings.json`. Секреты профилей и пароли серверов защищены DPAPI текущего пользователя Windows и лежат отдельными файлами (`profile-*.dat`, `server-*.dat`); WebView2 имеет отдельный постоянный каталог для каждого сервера. Имя и настройки звонка живут в хранилище этого WebView2. Тексты сообщений и содержимое вложений туда не сохраняются. Скачанные пользователем файлы остаются обычными локальными файлами. Для изолированного тестового профиля можно задать `CORD_PROFILE_DIRECTORY` перед запуском.

## Проверено и что осталось измерить

8 сентября 2026: Release-публикация и установщик собраны, **16 C#-тестов пройдено**. Проверены настоящая загрузка ресурсов WinUI, установка в новую папку, повторная установка и удаление с сохранением постороннего файла. Найдено и исправлено отсутствие PRI/XBF в обычной публикации. Главная в desktop-режиме проверена браузерными тестами и снимками обеих тем; общий набор — **24 Vitest и 9 Playwright**.

9 сентября 2026: [Windows CI на GitHub](https://github.com/MikkiMays/ModernStreamingSystem.Windows/actions/runs/34319798573) прошёл полностью, включая повторную сборку установщика на чистом runner. Проверенные локально установщик и ZIP опубликованы в релизе `v0.2.1`; размеры и SHA-256 файлов на GitHub сверены с локальными оригиналами.

Нативное окно ранее запускалось, но обновлённая анимация SplitView и диалоги устройств вручную до конца не проверены: управление окнами остановлено по пользовательскому Escape. Ресурсы проверялись отдельно через скрытый запуск без активации окна. Установка WebView2 на чистой VM остаётся отдельной проверкой.

Общие сценарии встреч проверяются браузерным набором соседнего проекта с настоящим SFU и синтетическими источниками. Реальная смена VPN, мобильные устройства, TURN/TLS, аппаратные 1440p60, задержки и нагрузочная приёмка ещё требуют выделенного стенда. Отдельный Windows.Graphics.Capture/нативный WebRTC-адаптер, MSIX и подпись издателя пока не сделаны. Текущий захват реализован через WebView2 и общий `CaptureAdapter`. Установленная версия обновляется сама; переносимый ZIP — нет, его заменяют вручную.
