# Cord для Windows

C#-приложение для общего ядра ModernStreamingSystem. Нативное окно WinUI 3: Mica, спокойная боковая панель, системная тема, избранное и настройки сервера. Встреча работает внутри постоянного WebView2 через тот же React/LiveKit-клиент, что и браузер. Поэтому телефон, веб и Windows входят в одни комнаты, используют общие права, чат, файлы и правила восстановления.

## Запуск готовой сборки

Скачайте **[Cord-Setup-0.2.2-x64.exe из релиза](https://github.com/MikkiMays/ModernStreamingSystem.Windows/releases/latest)** и запустите его. Для передачи на другой компьютер достаточно этого одного файла: установщик включает приложение, библиотеки, .NET, Windows App SDK и автономный пакет WebView2 Runtime. Установка выполняется для текущего пользователя без прав администратора, создаёт ярлык в «Пуск» и поддерживает обновление/удаление. [Подробная инструкция](docs/installer.md).

В том же релизе доступен переносимый `Cord-win-x64.zip`: распакуйте **всю** папку и запустите `Cord.exe`. Он требует установленный WebView2 Runtime. Сборки предназначены для Windows x64, минимум Windows 10 build 19041; рекомендуемая система — Windows 11. Наш установщик пока не подписан сертификатом издателя. При локальной сборке эти файлы создаются в `artifacts/`; бинарные файлы распространяются через Releases, исходники — через Git.

Ядро, веб-клиент и VPS-конфигурация находятся в [ModernStreamingSystem](https://github.com/MikkiMays/ModernStreamingSystem). Для совместной разработки клонируйте оба репозитория в соседние каталоги:

```powershell
git clone https://github.com/MikkiMays/ModernStreamingSystem.git
git clone https://github.com/MikkiMays/ModernStreamingSystem.Windows.git
```

По умолчанию новая установка подключается к **`https://meet.nikg.tech`**. Ранее сохранённый адрес сервера сохраняется при обновлении. Для локальной разработки укажите `http://localhost:5173` в настройках и запустите ядро из соседнего проекта:

```powershell
cd ..\ModernStreamingSystem
.\scripts\start-local.ps1 -JavaHome C:\Java\jdk-25
```

Чтобы использовать другой сервер, укажите HTTPS-адрес **веб-приложения** в настройках Cord. Приложение обращается к `/api/v1` этого же origin. URL отдельного LiveKit указывать здесь не нужно. `localhost` относится только к текущему компьютеру; для телефона и других компьютеров нужен общий HTTPS-сервер. Сборка не запускает VPS/ядро внутри себя.

## Возможности

- Главная, создание встречи, вход по ссылке/девятизначному коду, до пяти избранных комнат под основными кнопками и в нативной панели.
- Сохранённая комната сохраняет название и код, пока есть в избранном хотя бы одного профиля. Завершённый разговор можно открыть снова; сроки старых сообщений и файлов не продлеваются.
- Имя, устройства, тема и профили качества сохраняются между запусками. Название встречи задаётся при создании. Камера и микрофон по умолчанию выключены.
- На предпросмотре шестерёнка в правом нижнем углу открывает устройства и качество. Разрешения камеры/микрофона запрашиваются нативным диалогом; разрешённый доступ запоминается для этого сервера. В настройках есть сброс разрешений.
- Общие звонки, демонстрация до 1440p60, 15/30/60 fps, сообщения и временные файлы. Просмотр экрана и камеры ведущего в углу или рядом, личное закрепление участника и экрана.
- Уведомление Windows о смене сети ускоряет общий механизм восстановления с фиксированным сроком 20 секунд. Ручной/автоматический возврат подписок к живому эфиру не перезапускает собственный захват.
- Компактная панель подключения по центру главной без прокрутки страницы. На низком окне избранное открывается отдельным диалогом. Нативный SplitView анимирует сворачивание боковой панели; постоянный WebView2 и медиасессия сохраняются. На узком окне навигация и настройки остаются в меню. Размер при запуске учитывает рабочую область монитора. Полноэкранная демонстрация скрывает оболочку и занимает монитор. Закрытие во время звонка отправляет явный выход.

Избранное принадлежит анонимному профилю клиента. Установка Windows и отдельный браузер имеют разные профили; вход на другом устройстве возможен по приглашению/коду, после чего комнату можно сохранить там. Автоматической синхронизации профилей между устройствами пока нет.

## Сборка из исходников

Из корня этого каталога, PowerShell:

```powershell
# Скачает локальный SDK с проверкой SHA-512, выполнит тесты, соберёт Release
.\scripts\build.ps1

# Тесты, автономная публикация, ZIP и его SHA-256
.\scripts\build.ps1 -Publish

# Публикация и отдельный установщик со всеми зависимостями
.\scripts\build-installer.ps1

# Проверка ресурсов опубликованного WinUI и полного цикла установки
.\scripts\verify-publication.ps1
.\scripts\test-installer.ps1

# Запуск опубликованного приложения; при отсутствии сначала соберёт его
.\scripts\run.ps1
```

Глобальная установка .NET/Visual Studio не требуется для этих скриптов. Первый запуск скачивает SDK и пакеты NuGet. Версии закреплены `global.json`, `.csproj` и `packages.lock.json`.

```powershell
.\.local\dotnet\dotnet.exe restore Cord.slnx --locked-mode -p:Platform=x64
.\.local\dotnet\dotnet.exe test --project tests/Cord.Core.Tests/Cord.Core.Tests.csproj
.\.local\dotnet\dotnet.exe format whitespace Cord.slnx --verify-no-changes --no-restore
```

Тесты используют xUnit 4 и Microsoft.Testing.Platform; `--nologo` не является параметром этого тестового runner.

## Структура и данные

| Каталог | Ответственность |
| --- | --- |
| `src/Cord.Core` | Проверка server origin, HTTP-контракт избранного, типизированный bridge, source-generated JSON |
| `src/Cord.Windows` | WinUI, MVVM, WebView2, диалоги, жизненный цикл окна, DPAPI и сеть |
| `tests/Cord.Core.Tests` | Origin/bridge, HTTP-контракт, изоляция и постоянство профилей |
| `scripts` | Сборка, публикация и проверки установки/удаления |
| `installer` | Установщик Inno Setup, закреплённые зависимости и информация об установке |
| `.github/workflows/windows.yml` | Сборка, тесты и артефакт на Windows runner |

Настройки находятся в `%LOCALAPPDATA%\Cord\settings.json`. Секреты профилей защищены DPAPI текущего пользователя Windows; WebView2 имеет отдельный постоянный каталог для каждого сервера. Имя и настройки звонка живут в хранилище этого WebView2. Тексты сообщений и содержимое вложений туда не сохраняются. Скачанные пользователем файлы остаются обычными локальными файлами. Для изолированного тестового профиля можно задать `CORD_PROFILE_DIRECTORY` перед запуском.

## Проверено и что осталось измерить

8 сентября 2026: Release-публикация и установщик собраны, **16 C#-тестов пройдено**. Проверены настоящая загрузка ресурсов WinUI, установка в новую папку, повторная установка и удаление с сохранением постороннего файла. Найдено и исправлено отсутствие PRI/XBF в обычной публикации. Главная в desktop-режиме проверена браузерными тестами и снимками обеих тем; общий набор — **24 Vitest и 9 Playwright**.

9 сентября 2026: [Windows CI на GitHub](https://github.com/MikkiMays/ModernStreamingSystem.Windows/actions/runs/34319798573) прошёл полностью, включая повторную сборку установщика на чистом runner. Проверенные локально установщик и ZIP опубликованы в релизе `v0.2.1`; размеры и SHA-256 файлов на GitHub сверены с локальными оригиналами.

Нативное окно ранее запускалось, но обновлённая анимация SplitView и диалоги устройств вручную до конца не проверены: управление окнами остановлено по пользовательскому Escape. Ресурсы проверялись отдельно через скрытый запуск без активации окна. Установка WebView2 на чистой VM остаётся отдельной проверкой.

Общие сценарии встреч проверяются браузерным набором соседнего проекта с настоящим SFU и синтетическими источниками. Реальная смена VPN, мобильные устройства, TURN/TLS, аппаратные 1440p60, задержки и нагрузочная приёмка ещё требуют выделенного стенда. Отдельный Windows.Graphics.Capture/нативный WebRTC-адаптер, MSIX, подпись и автообновление не входят в эту переносимую сборку. Текущий захват реализован через WebView2 и общий `CaptureAdapter`.
